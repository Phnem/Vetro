# Источники рекомендаций: статус, условия, флаги

Документ к плану Recommendation Engine v2. Фиксирует, что реализовано, что включено по умолчанию и что нужно
проверить человеку **до релиза** (условия API проверить из среды разработки нельзя).

## Что включено по умолчанию

| Флаг (DataStore `settings`) | По умолчанию | Что делает |
|---|---|---|
| `rec_flag_tmdb` | вкл | TMDB: рекомендации, тренды, discover для фильмов и сериалов. Нужен `TMDB_API_KEY`; пустой ключ — источник молча выключен |
| `rec_flag_adaptive_mix` | вкл | Автоматическая пропорция аниме / фильмы+сериалы по составу коллекции. Выкл — только аниме, как раньше |
| `rec_flag_new_scorer` | вкл | Нормализованный скор [0,1] + MMR. Выкл — прежняя формула |
| `rec_flag_trakt_related` | **выкл** | Trakt `/related` как второй граф. Нужен `TRAKT_CLIENT_ID` |
| `rec_flag_tastedive` | **выкл** | TasteDive мультисид (legacy API). Нужен `TASTEDIVE_API_KEY` |
| `rec_flag_anidb` | **выкл, не реализовано** | Зарезервирован под AniDB (см. ниже) |

Смена любого флага меняет подпись кэша (`sourceFlags`) и пересобирает пул при следующем обновлении.
Ключи — только в `local.properties` (шаблон: `local.properties.example`), в git не попадают.

## Статус источников

| Источник | Контент | Статус | Замечания |
|---|---|---|---|
| AniList | аниме | работает, **юридический блокер к проверке** | Условия AniList запрещают использование API в конкурирующих anime/manga list-сервисах без разрешения. Vetro — каталог/трекер: **до релиза проверить совместимость или получить письменное разрешение**. Вес связи (`recommendations.rating`) теперь сохраняется |
| Shikimori | аниме | работает | Основной источник при русском интерфейсе |
| Jikan (MAL) | аниме | работает как fallback | Усечённая выдача без жанров — скор опирается на связь с сидами |
| TMDB | фильмы, сериалы | работает (P0) | Фильм и сериал — разные эндпоинты и разные пространства id. Для публичного релиза нужна атрибуция TMDB в «О приложении»; коммерческое использование требует отдельной лицензии |
| Trakt | фильмы, сериалы | реализован, выключен | Публичные `/related` без OAuth. Постер и жанры добираются из TMDB по `ids.tmdb`. В «О приложении» нужна оговорка, что Trakt приложение не одобряет. Лимит не хардкодится: 429 → предохранитель |
| TasteDive | фильмы, сериалы | реализован, выключен | Legacy-API (миграция на Qloo). Кандидат принимается только при однозначном совпадении названия с TMDB. Включать только после офлайн-проверки match rate |
| AniDB | аниме | **не реализован — решение No-Go** | Старый HTTP API без TLS (cleartext заблокирован на Android), строгие лимиты и регистрация клиента, нет надёжного маппинга AID → AniList/MAL. Возвращаться, если появится HTTPS-доступ и разрешённая модель доступа. Скрейпинг HTML как обход не допускается |

## Go / No-Go перед включением выключенного

- **Trakt:** получен Client ID; на живом ключе `/movies/{id}/related` и `/shows/{id}/related` отвечают без OAuth;
  замерена доля уникальных кандидатов относительно TMDB; оговорка в «О приложении».
- **TasteDive:** ключ получен; на тестовых коллекциях match rate с TMDB достаточен; сервис ещё доступен.
- **AniDB:** см. выше — не включать.

## Как это устроено

- `ContentMixResolver` — пропорция 20 карточек; `QuotaAllocator` — чередование типов.
- `SeedSelector` — 6–10 разнообразных сидов (MMR по тегам), без брошенного и оценённого ниже 6.
- `CandidateMerger` — склейка внутри типа: типизированные id → название (+ год для кино). `MOVIE:123` ≠ `TV:123`.
- `NormalizedScorer` — `0.30·G + 0.35·R + 0.15·Q + 0.15·F + 0.05·D`, перенормировка отсутствующих компонентов,
  Bayesian-качество, шум-ИЛИ по разным сидам. Веса — гипотеза, подбираются на replay-тестах.
- `DiversityReranker` — MMR (λ=0.8) внутри типа до квот.
- `SourceCircuitBreaker` — 3 отказа подряд отключают источник на 15 минут; пустой ответ отказом не считается.
- Оценка свайпом (вверх / вниз) → `FeedbackStore` → профиль вкуса, доверие к сиду, исключение из выдачи.

## Метрики качества

Офлайн-метрики (Recall@20, NDCG@20) требуют размеченных коллекций и в репозитории не посчитаны; тесты
`ReplayCollectionsTest` проверяют состав колоды для типовых коллекций, а `NormalizedScorerTest` — инварианты скора.
Телеметрии приёма карточек в приложении нет (оценки свайпом хранятся только на устройстве).
