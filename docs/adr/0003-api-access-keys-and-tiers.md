# 0003 — Доступ к API каталога: ключи, подтверждение приложения, тарифы, бот, панель

Статус: принято (2026-11-13), реализуется по фазам. Код — `tools/books-api/` (Worker), позже `tools/books-admin/` (бот и панель).
Контекст: API (`api.vetrostudio.bid`, ADR 0002) был полностью открыт; адрес достаётся из APK за минуты.

## Что защищаем и от чего

Нельзя сделать так, чтобы адрес API «нельзя было вытащить из кода»: он в APK, это не секрет. Защищается другое:

1. **Анонимный сбор каталога.** Любой клиент без ключа получает 401 (кроме `/v1/health`). Закрыто всё остальное, включая файлы индекса
   (весь телефонный каталог одним файлом) и обложки.
2. **Подмена приложения.** Ключ приложения выдаётся только установке, которая доказала серверу, что работает **настоящее** приложение
   (подпись APK из списка). Скрипт, вытащивший адрес, ключ не получит.
3. **Безлимитное стороннее использование.** Сторонние клиенты (сайт, партнёры, покупатели через бота) работают по собственным ключам с
   лимитами тарифа; ключ можно отозвать, лимиты и расход видны в панели.

Приложение при отказе API (401/403/429/нет сети) молча идёт по прежним источникам: API — первое звено цепочки, а не единственное.

## Подтверждение приложения: Android Key Attestation (не «проверка подписи» внутри приложения)

Проверка подписи, которую приложение делает **у себя** (как для Cast и автообновления), серверу ничего не доказывает: скрипт приложение
не запускает и может написать что угодно. Серверный аналог подписи — **аттестация ключа**: приложение создаёт ключ в аппаратном хранилище
(`AndroidKeyStore`, `setAttestationChallenge(nonce)`), телефон выдаёт цепочку сертификатов, подписанную корнем Google. В расширении
`1.3.6.1.4.1.11129.2.1.17` лежат **имя пакета, SHA-256 подписи APK, уровень защиты (TEE/StrongBox) и состояние загрузчика**. Сервер:

1. выдаёт одноразовый `nonce` (подписан, живёт минуту);
2. проверяет цепочку до корней Google (список корней: `https://android.googleapis.com/attestation/root`, обновляется скриптом);
3. сверяет `challenge == nonce`, пакет `com.phnem.vetro`, подпись из белого списка (панель: «Подписи»: релизная, F-Droid, debug для `.perf`);
4. принимает только TEE/StrongBox; программная аттестация (эмулятор, старый телефон) отклоняется;
5. выдаёт токен установки `va_…` (HMAC, срок 30 дней, продлевается повторной аттестацией).

Работает без Google Play и на F-Droid-сборках. Кто не прошёл (старое железо, кастомные прошивки без аттестации, эмуляторы), остаётся на старых
источниках. Это осознанная цена за то, что подделать цепочку без настоящего устройства нельзя. Не проверялось: поведение на конкретных
прошивках (GrapheneOS, microG); проверка на Xiaomi 13 из проекта — первый шаг фазы 2.

## Ключи

- Формат: `vk_<тариф>_<32 символа>` (сторонние), `va_<данные>.<подпись>` (установки приложения).
- В базе хранится только SHA-256 ключа (`api_keys.key_hash`) и префикс для показа; сам ключ видно один раз, при выдаче.
- Передача: `Authorization: Bearer …` или `X-Api-Key`; для `<img>` (обложки на сайте) допустим `?key=` и **только** на `/covers/*`.
- У ключа: тариф, статус (`active/revoked`), срок, список допустимых источников запроса (`allowed_origins`, для ключей на страницах сайта:
  браузер сам ставит `Origin`), владелец (Telegram), метка.
- Проверка ключа кэшируется на краю на 60 с: отзыв действует в пределах минуты.

## Тарифы (для сторонних; приложению лимиты тарифов не применяются)

Лимиты: «в секунду» (всплеск), «в минуту» (частота), «в сутки» (по UTC). Цены — **заготовка в Telegram Stars**, меняются в панели
(таблица `tiers`), срок 30 дней.

| | Basic | Pro | Ultra |
|---|---|---|---|
| Запросов в секунду | 2 | 5 | 20 |
| Запросов в минуту | 30 | 120 | 600 |
| Запросов в сутки | 2 000 | 20 000 | 200 000 |
| Поиск: результатов за запрос | до 20 | до 50 | до 50 |
| Пакет `?ids=` | до 10 | до 40 | до 40 |
| Обложки | нет | да (small + large) | да |
| Файлы индекса (весь каталог для офлайна) | нет | нет | **да** |
| Карточки с подробностями | да | да | да |
| Ключей на покупателя | 1 | 2 | 5 |
| Цена за 30 дней (заготовка) | 100 ⭐ | 400 ⭐ | 1 500 ⭐ |

«Скорость» понимается как частота и всплеск (запросы в секунду); отдельного ограничения полосы нет. Расход по маршрутам считается и виден
в панели. Тариф `app` (внутренний, не продаётся): установка приложения, 120 запросов в минуту, без суточного лимита.

## Учёт и лимиты (реализация)

- На ключ — один Durable Object `KeyMeter`: счётчики секунды, минуты и суток; ответ `429` с `Retry-After` и заголовками `X-RateLimit-*`.
  Счётчик суток и расход по маршрутам сбрасываются в D1 (`usage_daily`) раз в минуту при активности.
- Лимиты тарифа лежат в D1 (`tiers`), правятся в панели без деплоя; кэш на краю 60 с.
- `ACCESS_MODE` в `wrangler.toml`: `open` (ключ необязателен, но если пришёл, проверяется) или `enforce` (без ключа 401). Рубильник на случай
  аварии. До выхода приложения с токеном — `open`.

## Бот в Telegram (фаза 3)

`/start`, `/plans` (тарифы), `/buy <тариф>` (счёт в Stars, `sendInvoice` в XTR, подтверждение `successful_payment` выдаёт ключ),
`/key` (мои ключи, показ префикса), `/rotate` (перевыпуск), `/usage` (расход за сутки и месяц), `/revoke`. Хранение: `customers`, `orders`
(`charge_id` уникален: повторная доставка платежа не выдаёт второй ключ). Вебхук с секретным заголовком. Токен бота и ключ вебхука —
секреты Worker, вводит владелец (`wrangler secret put`), я их не вижу.

## Панель (фаза 4)

Отдельный Worker `vetro-books-admin` на `dash.vetrostudio.bid` за **Cloudflare Access** (вход по e-mail владельца): ключи (выдать, отозвать,
сменить тариф и срок), тарифы и цены, покупатели и заказы, расход по ключам и маршрутам, установки приложения, белый список подписей APK,
рубильник `ACCESS_MODE`.

## Фазы

1. **Ключи, тарифы, лимиты, учёт** (этот ADR, `src/access.js`, `schema/access.sql`, тесты).
2. **Аттестация и приложение:** `/v1/auth/challenge`, `/v1/auth/register`, токены `va_`, клиент в приложении, откат на старые источники.
3. **Бот в Telegram.**
4. **Панель и Cloudflare Access.**
5. **Включение:** вход в Cloudflare (`wrangler login`), миграция D1, деплой, `ACCESS_MODE = "enforce"` после выхода приложения.
