# API каталога книг Vetro

API только для чтения: поиск, карточки книг с описаниями, жанрами и сериями, обложки.
Адрес: `https://api.vetrostudio.bid`. English version: [README.md](README.md). Условия использования: [terms.ru.md](terms.ru.md).

| | |
|---|---|
| Формат | JSON, UTF-8; обложки — изображения AVIF |
| Протокол | только HTTPS, для браузеров включён CORS |
| Каталог | около 269 000 книг и около 190 000 аниме, фильмов и сериалов, с обложками, регулярно пополняется |
| Доступ | ключ на каждого клиента, выдаётся ботом в Telegram, три тарифа |
| Доступность | по возможности, без гарантии бесперебойной работы (см. [условия](terms.ru.md)) |

## Как получить ключ

1. Откройте бота Vetro API в Telegram (ссылка на сайте Vetro Studio) и выберите язык.
2. Расскажите боту о проекте: название, краткое описание, тип (сайт, мобильное приложение, сервер, другое), домены (для сайтов),
   коммерческий ли проект и сколько запросов в сутки примерно ожидаете. Бот посоветует тариф.
3. Прочитайте и примите [условия](terms.ru.md), оплатите тариф в Telegram Stars (30 дней за платёж).
4. Бот покажет ключ **один раз**. Сервис хранит только его хэш. Если ключ потерян, `/rotate` выдаст новый.

Команды бота: `/plans` тарифы и цены, `/buy` новый ключ или продление, `/key` ваши ключи и сроки, `/rotate` заменить ключ,
`/usage` счётчики запросов, `/revoke` отключить ключ, `/lang` язык, `/cancel` выйти из диалога.
Цены и лимиты ниже действуют сейчас; перед оплатой бот всегда показывает актуальные значения.

## Тарифы

| Тариф | В секунду | В минуту | В сутки (UTC) | Потолок `limit` / `ids` | Обложки | Офлайн-индекс | Цена за 30 дней |
|---|---|---|---|---|---|---|---|
| Basic | 2 | 30 | 2 000 | 20 / 10 | нет | нет | 100 ⭐ |
| Pro | 5 | 120 | 20 000 | 50 / 40 | да | нет | 400 ⭐ |
| Ultra | 20 | 600 | 200 000 | 50 / 40 | да | да | 1 500 ⭐ |

«В секунду» — размер всплеска, а не ограничение скорости. Значения `limit` и `ids` выше потолка тарифа обрезаются, а не отклоняются.
Ключ для сайта работает только с доменов, которые вы назвали боту.

## Аутентификация

Ключ передаётся одним заголовком:

```http
Authorization: Bearer vk_pro_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Принимается и `X-Api-Key: vk_…`. Для тегов `<img>`, где заголовки не задать, обложки принимают ещё `?key=vk_…`.
Ключ выглядит как `vk_<тариф>_<32 символа>`. Без ключа работает только `GET /v1/health`.

## Запросы

Все пути относительно `https://api.vetrostudio.bid`. Идентификаторы книг — девятизначные строки (`000000771`).

### `GET /v1/health`
`{"ok":true}`. Ключ не нужен.

### `GET /v1/search?q=<текст>&limit=<n>`
Полнотекстовый поиск по названиям и авторам на обоих языках. `limit` по умолчанию 20, потолок задаёт тариф.

```json
{ "q": "dune", "items": [
  { "id": "000001192", "ru": "Дюна", "en": "Dune series", "ra": "Кевин Джей Андерсон", "ea": "Kevin J. Anderson", "y": 1965, "f": 5, "cv": 6013617 }
] }
```

`ru`/`en` названия, `ra`/`ea` авторы, `y` год, `cv` ревизия обложки (подставляйте как `?v=` при запросе обложки),
`f` флаги: бит 1 — есть обложка, бит 2 — у обложки ограниченная лицензия (см. [условия](terms.ru.md)), бит 4 — ядро каталога.

### `GET /v1/books/{id}` и `GET /v1/books?ids=1,2,3`
Одна книга с карточкой деталей или до `ids` (потолок тарифа) книг без деталей. В карточке необязательные ключи: `orig` оригинальное
название, `type`, `alts` другие названия, `authors`, `series`, `tr` переводы, `ed` издания, `ext` внешние id, `cover`, `desc`
`{t, l}` описание и его язык, `gen` ключи жанров (`scifi`, `fantasy`, …; названия подставляет клиент), `ol` язык оригинала,
`coll` признак сборника, `ch` главы, `dur` типичная длина в минутах, `rate` `{v, n}` оценка и число голосов. Любой ключ может отсутствовать.

### `GET /covers/{small|large}/{id}.avif?v={cv}`
Обложка. Нужен тариф с обложками. AVIF показывают браузеры и Android 12 и новее; для старых систем нужен другой источник.
Ответы неизменяемы: кэшируйте навсегда, а при смене `cv` меняйте `v`.

### Аниме, фильмы и сериалы: `/v1/media/...`

В том же каталоге около 190 000 аниме, фильмов и сериалов (названия русские, английские, ромадзи и на языке оригинала).
Эти маршруты используют тот же ключ, те же лимиты тарифа и те же ошибки, что и книжные: `/v1/media/search` считается поиском,
карточки и пакеты — запросами книг, обложки — обложками.

- `GET /v1/media/search?q=<текст>&type=<anime|movie|tv>&limit=<n>`: `type` необязателен. Порядок по релевантности с поправкой на известность тайтла.
- `GET /v1/media/{id}`: один тайтл с карточкой. Идентификатор — буква и восемь цифр: `A` аниме, `M` фильм, `S` сериал (`A00000050`).
- `GET /v1/media?ids=A00000050,S00000110`: до `ids` (потолок тарифа) тайтлов, только строки.
- `GET /covers/media/{small|large}/{id}.avif?v={cv}`: обложки, правила как у книжных.

```json
{ "q": "attack on titan", "items": [
  { "id": "A00000050", "t": "anime", "ru": "Атака титанов", "en": "Attack on Titan", "ro": "Shingeki no Kyojin", "orig": "進撃の巨人", "y": 2013, "st": "tv", "f": 3, "cv": 11003245 }
] }
```

Ключи строки: `t` — `anime`, `movie` или `tv_series`; `ru`, `en`, `ro` (ромадзи), `orig` названия; `y` год; `st` подтип (`tv`, `movie`, `ova`, `special`, …); `f` флаги
(бит 1 — есть обложка, бит 2 — у обложки ограниченная лицензия); `cv` ревизия обложки. В карточке (`detail`) необязательные ключи: `desc` `{t, l}`
описание и язык, `gen` жанры, `fr` `{t, i, n}` название франшизы, место и размер, `ol` язык оригинала, `seas` сезоны, `eps` серии,
`dur` минут в серии, `st` статус выхода, `ext` идентификаторы в других базах (`mal`, `shikimori`, `anilist`, `kitsu`, `tmdb`, `imdb`, `tvmaze`, `tvdb`, `wikidata`)
и `cover` `{src, lic, w, h}` источник и лицензия обложки. Поиск понимает латиницу, кириллицу и транслитерацию; японские иероглифы не ищутся.
Часть тайтлов есть и как `anime`, и как `tv_series`: они пришли из разных баз.

### `GET /v1/manifest` и `GET /v1/index/...` (Ultra)
Офлайн-индекс поиска из приложения Vetro: манифест и версионные файлы базы и дельт (SQLite в zstd). Поддерживается `Range`.

## Ответы, кэш и лимиты

Успешные ответы несут `X-RateLimit-Limit-Minute`, `X-RateLimit-Remaining-Minute`, `X-RateLimit-Limit-Day`, `X-RateLimit-Remaining-Day`.
Ответы поиска и книг кэшируются на краю (10 минут и сутки). Учитывайте `Cache-Control` и `ETag`, где они есть.

Ошибки — JSON `{"error": "<код>"}`:

| Статус | `error` | Значение |
|---|---|---|
| 401 | `missing_key`, `invalid_key` | нет ключа или он неизвестен |
| 403 | `key_revoked`, `key_expired` | ключ отозван или 30 дней закончились; продлите в боте |
| 403 | `origin_not_allowed` | запрос из браузера с домена, которого нет в ключе |
| 403 | `tier_forbids_route` | обложки или индекс на тарифе без них |
| 429 | `rate_limited` | упёрлись в лимит: `scope` — `second`, `minute` или `day`; подождите `retry_after` секунд (заголовок `Retry-After`) |
| 400, 404 | | неверный запрос, нет такой книги |

На 429 и 5xx повторяйте с нарастающей паузой; остальные 4xx не повторяйте.

## Быстрый старт

```js
const API = "https://api.vetrostudio.bid";
const KEY = "vk_pro_...";
const res = await fetch(`${API}/v1/search?q=${encodeURIComponent("Дюна")}&limit=5`, { headers: { Authorization: `Bearer ${KEY}` } });
const { items } = await res.json();
const cover = `${API}/covers/small/${items[0].id}.avif?v=${items[0].cv}&key=${KEY}`; // для <img src>
```

```bash
curl -H "Authorization: Bearer $KEY" "https://api.vetrostudio.bid/v1/books/000000771"
```

## Технические характеристики

- Работает на Cloudflare Workers у границы сети; данные в Cloudflare D1 (SQLite с FTS5) и R2 (обложки, файлы индекса).
- Ответы отдаются с краевых серверов Cloudflare: кэшированные быстрые, поиск, дошедший до базы, дольше. Скорость не гарантируется.
- Метаданные запросов (IP-адреса, user agent) не пишутся. Хранятся счётчики по ключам (запросы по маршрутам и дням): для тарифов и `/usage`.
- Каталог обновляется без простоя, идентификаторы стабильны. В ответах могут появляться новые поля: неизвестные ключи игнорируйте.
- Изменения, ломающие существующих клиентов, выйдут под новым префиксом (`/v2`).
