# vetro-books-admin: панель владельца API каталога

ADR 0003, фаза 4. Отдельный Cloudflare Worker на `dash.vetrostudio.bid`, общая база D1 `vetro-books` с API и ботом.
Вход только через Cloudflare Access; без настроенного Access воркер на всё отвечает 503.

## Что умеет

- **Обзор:** активные ключи, запросы за 14 дней по маршрутам, самые активные ключи сегодня, Stars за 30 дней, очередь уведомлений.
- **Ключи:** выдать (тариф, название, домены, срок или бессрочно; ключ показывается один раз), отозвать/вернуть, изменить тариф, домены и срок, расход за 30 дней.
- **Заявки:** анкета покупателя из бота, заметка, сообщение покупателю, отклонение (отзывает ключи и пишет покупателю), бан покупателя (отзывает все его ключи).
- **Установки приложения:** отзыв токена установки; список разрешённых подписей APK (добавить, отключить).
- **Тарифы:** правка лимитов, цены, срока, прав на обложки и индекс. API подхватывает за минуту (кэш 60 с).
- **Журнал:** кто и что менял (`admin_log`); открытые ключи в журнал не попадают.

Возврат Stars панель не делает: это команда `/refund` владельца в боте.

## Как это связано с ботом

Панель в Telegram не ходит (токена бота у неё нет). Уведомления покупателям она кладёт в таблицу `bot_outbox`
(`schema/bot.sql` в `tools/books-api`); бот читает её по расписанию (cron раз в минуту) и отправляет.

## Запуск (один раз)

1. Применить схему журнала: `npx wrangler d1 execute vetro-books --remote --file schema/admin.sql`.
2. Задеплоить: `npm run deploy`. Домен `dash.vetrostudio.bid` создастся сам; пока Access не настроен, ответ везде 503.
3. Cloudflare Zero Trust -> Access -> Applications -> Add -> Self-hosted: домен `dash.vetrostudio.bid`, политика Allow только ваш e-mail
   (One-time PIN или Google). После создания в Overview скопировать **Application Audience (AUD) Tag**;
   команда (team domain) вида `<team>.cloudflareaccess.com` лежит в Settings -> Custom pages.
4. Вписать в `wrangler.toml` `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `OWNER_EMAIL` и снова `npm run deploy`.

Воркер сам проверяет токен Access (подпись RS256 по ключам команды, aud, срок, e-mail владельца): прямой адрес в обход Access ничего не отдаст.

## Защита

- Все изменения только `POST/PATCH/PUT` с заголовком `x-dash: 1` и тем же Origin: с чужого сайта их не отправить.
- Страница с CSP `script-src 'self'`, данные покупателей в DOM попадают только как текст (нет `innerHTML`).
- Тексты уведомлений экранируются перед записью в очередь.

## Страница

Исходники в `web/`, воркеру они вшиты строками: после правки `python scripts/build-page.py`, затем `npm run deploy`.
