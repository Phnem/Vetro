# Расширение источников Vetro — исследование (2026-09-26)

Всё ниже проверено живыми запросами с машины разработчика (регион IL) и на публичных демо-серверах.
Сохранённые ответы — `app/src/test/resources/enrichment/` (станут фикстурами тестов).
Ключей OpenSubtitles, OMDb, YouTube, Fanart.tv, NYT, TasteDive у проекта нет: для них проверены

### Чему Vetro стоит научиться у этих проектов

- **anime-sdk** — единое пространство ID `provider:rawId`; каскад сопоставления «кэш → родной поиск
  провайдера → внешние маппинги → нечёткое сравнение с проверкой года, типа и числа серий»; лимит на хост
  с вторичным окном всплеска; `Retry-After`; прокси с белым списком хостов (защита от SSRF).
- **Anify** — модель «каноническая сущность → маппинги → сущность провайдера → единицы контента →
  источники»; маппинг хранится в БД, а не вычисляется при каждом запросе.
- **SerienStreamAPI** — поток описывается тройкой «хостер × язык аудио × язык субтитров»: так же
  стоит группировать озвучки в Vetro.
- **AllAnime / hianime** — явный режим `sub/dub` на уровне списка серий (у каждого режима свой счёт
  вышедших серий).
- **TMDB-Embed-API** — тайминги по каждому провайдеру в ответе (`providerTimings`) и включаемые
  провайдеры — удобная диагностика.
- **Subsonic** — одним адаптером закрывается семейство серверов; возможности сервера видны через
  `getOpenSubsonicExtensions` — такой же «рукопожатием по возможностям» стоит сделать импорт пакетов.
- **Чего не брать:** исполнение стороннего кода, расшифровку ответов сайтов, прокси-обход Referer,
  iframe-плееры.
