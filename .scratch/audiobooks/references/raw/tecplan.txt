# План: Vetro Audiobooks — третий класс медиа в Vetro Collection

## 1. Суть задачи
Добавить в Vetro Collection третий класс контента — **аудиокниги** — поверх уже существующих двух (манга и видео: аниме/сериалы/фильмы). Используем ту же философию, что и для видео: существующий подход к парсингу, стримингу и скачиванию переносится на аудио, но с других сайтов. Начинаем с «базовой оболочки» плеера, поверх которой полностью перерисовывается UI под Vetro.

## 2. Ядро воспроизведения (базовая оболочка)
- **AndroidX Media3 / ExoPlayer 1.11.1** — тот же движок, что уже используется для видео, но в отдельном слое приложения:
  - `androidx.media3:media3-exoplayer:1.11.1`
  - `androidx.media3:media3-session:1.11.1`
  - `androidx.media3:media3-ui-compose:1.11.1`
- **Никакого PlayerView и никаких готовых Material-компонентов**: `media3-ui-compose` берём только как state-holder'ы (play/pause/currentItem/progress), весь экран рисуем сами с нуля под Vetro.
- **MediaSessionService** — штатная архитектура Media3 для аудиокниг: фоновое воспроизведение, lockscreen, Bluetooth-гарнитуры, системная media-notification, восстановление после убийства приложения.
- **Скачивание не пишем с нуля** — используем Media3 `DownloadService` для offline-медиа (книга целиком / по главам).
- **Стриминг напрямую с URL**, с cookies/headers под особенности источников; автоматическое продолжение следующей главы.
- Парсер полностью отделён от плеера: `сайт → parser → resolveAudio() → AudioStream(url, headers, mimeType) → MediaItem → ExoPlayer`. Это точная копия нынешней архитектуры anime-streaming, только вместо `VideoStream` — `AudioStream`.

## 3. UI — визуально списываем с аниме и фильмов
**Весь визуал страниц аудиокниг делаем почти 1-в-1 с уже существующими страницами аниме и фильмов**, чтобы класс выглядел родным внутри Vetro:
- **Страница details книги** — почти 1-в-1 с details аниме/фильма: большая обложка, название, автор, описание, жанры, метаданные, кнопки действий; блок озвучек оформляем как блок озвучек у аниме (только вместо озвучек — чтецы).
- **Список глав** — почти 1-в-1 со списком серий у аниме/сериалов: номер, название, длительность, отметка прогресса просмотра/прослушивания, иконка скачивания.
- **Поиск и выдача** — те же сетки/списки карточек, что и в остальных классах Vetro.
- **Экран плеера** — полностью кастомный, в общем визуальном языке приложения: большая обложка книги, название/автор, «Глава 7 из 42», собственный waveform/progress, кнопки −15 сек / Play / +30 сек, скорость 0.5×–3×, sleep timer, список глав, bookmarks, процент книги и «осталось 3ч 42м».
- **Mini-player** внизу всех экранов Vetro с плавным переходом mini → fullscreen, стилистически как остальные элементы приложения.
- **Шторка**: принимаем как факт, что на Android 13+/API 33 системный media-control рисует сама System UI из MediaSession — в шторке нативный Android-контрол (обложка, название, глава, play/pause, prev/next, перемотка, progress), а полностью кастомный Vetro-UI живёт только внутри приложения. Это и есть целевой UX.

## 4. Модель данных и агрегация
- Сущности фиксируем в три уровня: **CanonicalWork → Narration (чтец) → ProviderVariant (источник) → MediaManifest → Chapter[]**.
- Поиск идёт параллельно по всем источникам → normalizer →_merge дублей: пользователь видит одну карточку («Мастер и Маргарита, 3 озвучки»), внутри — выбор чтеца, у каждого чтеца — список источников с приоритетами.
- Воспроизведение: выбранная Narration → все её ProviderVariant → убрать недоступные/неразрешённые → сортировка priority DESC, health DESC → попробовать #1 → #2 → #3 → error.
- Приоритет динамический: если источник за последние запросы начал отдавать ошибки, он временно опускается ниже соседей.
- **Source fingerprint**: у каждого источника храним `catalogueHost / mediaHost / cdnHost → infrastructureGroup`. Fallback группируется по инфраструктуре, а не по имени сайта: два «разных» сайта с одним медиа-хостом — одна failure-domain и не должны стоять друг за другом как независимые резервы.

## 5. Интерфейс источников
```kotlin
interface AudiobookSource {
    val capabilities: Set<Capability>
    suspend fun search(query: String): List<Book>
    suspend fun details(id: String): BookDetails
    suspend fun chapters(id: String): List<AudioChapter>
    suspend fun stream(chapter: AudioChapter): AudioResource?
    suspend fun download(chapter: AudioChapter): AudioResource?
}
enum class Capability {
    SEARCH, DETAILS, NARRATIONS, CHAPTERS,
    STREAM, DOWNLOAD, OFFLINE, AUTH_REQUIRED, RIGHTS_VERIFIED
}
```
Источник не обязан уметь playback, чтобы приносить пользу: metadata-only источник тоже участвует в агрегации (обогащает карточку, озвучки, дубли).

## 6. Источники (финальный набор)
### 🇷🇺 RU — по приоритету
1. **Aknigi24** — основной: очень глубокий каталог (включая сборники и разные озвучки), страницы авторов, стриминг и скачивание без регистрации.
2. **Audiokniga.one** — второй: структурно идеален под модель Work → Narration (одна страница книги знает множество чтецов), структурированные главы, исполнитель, длительность, циклы.
3. **Knigavuhe** — третий: сильные metadata, различение автора и чтеца, произведений и сборников, много альтернативных озвучек; часть книг бывает «ограничена по просьбе правообладателя» — это штатный сценарий fallback на следующий источник.

**Резерв (challengers):** Akniga (каталог отличный, но robots.txt закрывает `/stream/` и `/ajax/` — используем в первую очередь как search/metadata-слой), AudioTales, Audio-Knigi-Online, Audioboo (нестабильный доступ, 403 — держать последним рубежом).

### 🇬🇧 EN — по приоритету
1. **RealAudiobooks** — основной: author, narrator, duration, language, genres, полноценный player, главы/треки, полное бесплатное воспроизведение современных книг.
2. **GoldenAudiobooks** — второй: современные книги разбиты на отдельные MP3-части со структурированной последовательностью файлов — удобно для глав и скачивания.
3. **AudioAZ** — третий: хорошая структура книг и глав, разные озвучки одних и тех же произведений.

- **101Audiobooks — не четвёртый источник**: он и GoldenAudiobooks отдают медиа с одного хоста `ipaudio.club`, то есть это зеркало/родственник в одной infrastructureGroup (учитывать в fallback как одну failure-domain).

## 7. Этапы работ
1. **Оболочка плеера**: Media3 + MediaSessionService, кастомный Compose-экран плеера, mini-player, системный media-control в шторке/lockscreen.
2. **Локальная библиотека**: аудиокниги как полноценный класс local-first библиотеки (рядом с Movies/Series/Anime/Manga): запоминание позиции отдельно для каждой книги, bookmarks, процент, статистика.
3. **Адаптеры источников**: реализации `AudiobookSource` для RU- и EN-тройки (+ challengers опционально): search → details → chapters → resolveAudio, headers/cookies под каждый сайт.
4. **Агрегатор**: параллельный поиск, normalizer, дедупликация Work → Narration → ProviderVariant, fallback с динамическим приоритетом и учётом infrastructureGroup.
5. **Offline**: Media3 DownloadService — скачивание книги/глав, воспроизведение без сети, менеджмент загрузок в стиле видео-класса.
6. **Дополнения**: sleep timer, скорости 0.5×–3×, автопереход на следующую главу, RU/EN локализация, увязка с трекингом и рекомендациями Vetro.
