# AB-05 — источники-якоря: LibriVox, Internet Archive, Audiobookshelf, Local Folder

Дата проверки: 2026-09-23. Область: официальная документация поставщиков и Android, плюс единичные живые GET-запросы к публичным API LibriVox/Internet Archive. Для Audiobookshelf сервер пользователя и токен не предоставлены; контракт не проверялся на живом экземпляре. Другие сайты из AB-05 здесь не исследованы. Все ссылки ниже ведут непосредственно к первичным источникам.

| Якорь | Доступ и предполагаемые возможности | Постоянный внешний ключ | Сила свидетельства |
| --- | --- | --- | --- |
| LibriVox | Публичный каталог; поиск title/author/genre, детали, секции/читатели, обложки, аудио и архив | `librivox:<book.id>`; секция — `book.id + section.id` | Высокая: [официальный API](https://librivox.org/api/info) и проверенный ответ книги 52 |
| Internet Archive | Публичный поиск/метаданные, файлы, обложки и аудио при доступности конкретного item | `ia:<identifier>`; файл — `identifier + name` | Высокая: [официальный MDAPI](https://archive.org/developers/md-read.html), [item URLs](https://archive.org/developers/items.html) и проверенный item |
| Audiobookshelf | Пользовательский сервер: библиотеки, поиск, детали, треки, обложки, playback session, прогресс | `abs:<server-scope>:<libraryItem.id>` | Средняя: [официальная справка API](https://api.audiobookshelf.org/) сама помечена устаревшей; живой сервер не проверен |
| Local Folder | Выбранное пользователем дерево SAF, локальные файлы/метаданные/обложки/воспроизведение | `local:<tree-uri>:<opaque-document-id>` | Высокая для API Android; конкретные DocumentsProvider отличаются и требуют device-тестов |

**Правило identity:** эти ключи пригодны как идентификаторы `SourceItem`/`Variant`, но не как вечный `workId`. `workId` остаётся UUID, а нормализованный hash — только `clusterFingerprint` согласно принятой архитектуре.

## LibriVox

- [Официальный API](https://librivox.org/api/info) описывает `GET https://librivox.org/api/feed/audiobooks`: параметры `id`, `since`, `author`, `title`, `genre`, `extended=1`, `coverart=1`, `limit`, `offset`, `format=json`; значения title/author/genre можно закрепить префиксом `^`. По умолчанию 50 записей, offset 0. Там же документирован `GET /api/feed/audiotracks?project_id=<book-id>` и отдельный authors endpoint. Аутентификация для этих публичных запросов в справке не указана; запрос книги 52 без авторизации вернул HTTP 200.
- В полях книги официально перечислены `id`, `title`, `description`, `language`, `num_sections`, `url_rss`, `url_zip_file`, `url_librivox`, `url_iarchive`, `totaltimesecs`, `authors`, `sections`, `coverart_jpg` и `coverart_thumbnail` ([список полей](https://librivox.org/api/info)). Живой `GET /api/feed/audiobooks/?id=52&format=json&extended=1&coverart=1` вернул 57 sections: `section_number`, `title`, `listen_url` MP3, `playtime`, `readers`; `GET /api/feed/audiotracks/?project_id=52&format=json` вернул их под ключом `sections`, а не `tracks`. В том же ответе `url_iarchive` указывает на `letters_brides_0709_librivox`, поэтому связь с IA можно сохранить как cross-source reference, не угадывая её из названия.
- [Объявление LibriVox от 2026-09-16](https://librivox.org/2026/09/16/librivox-api-update/) вводит максимальный `limit=500`, просит делать паузы в несколько секунд между запросами и предупреждает о возможном будущем rate limit. Адаптеру нужны ограничение страниц, кэш и уважение 4xx/429; массовый параллельный обход каталога не подходит.
- [Страница LibriVox о public domain](https://librivox.org/pages/public-domain/) утверждает статус записей в США и предупреждает о различиях прав в других странах. Это не универсальная лицензия для каждого региона.
- **Фикстуры:** сохранить компактный ответ `id=52&format=json&extended=1&coverart=1` с несколькими секциями и читателями; ответ `audiotracks?project_id=52`; search `title=letters&format=json&limit=2&offset=0`; пустой ответ для заведомо отсутствующего id. Для offline-теста использовать небольшой законно доступный MP3-фрагмент или синтетический аудиофайл, а не полный архив. Прямые медиа-ссылки и наличие Range/долговечность CDN отдельно проверить перед реализацией загрузки.

## Internet Archive

- [Advanced Search](https://archive.org/advancedsearch.php#raw) предлагает JSON, поля ответа, `rows` и `page`. Проверенный запрос `q=collection:librivoxaudio AND mediatype:audio AND title:Letters`, `fl[]=identifier`, `fl[]=title`, `rows=2`, `page=1`, `output=json` вернул `response.numFound=103` и массив `response.docs`. Поле `identifier` — внешний ключ item. Это поиск по IA metadata, и результаты могут иметь неполные/разнородные книжные метаданные.
- [MDAPI Read](https://archive.org/developers/md-read.html) документирует `GET https://archive.org/metadata/{identifier}` и JSON с `metadata` и `files`. [Описание item](https://archive.org/developers/items.html) подтверждает уникальный identifier и канонические ссылки `/details/<identifier>` и `/download/<identifier>/<filename>`. Не сохранять редирект на конкретный `iaNNN...us.archive.org`: IA прямо предупреждает, что серверная ссылка может сломаться после перемещения item.
- Проверенный `GET /metadata/letters_brides_0709_librivox` вернул `metadata.identifier`, `title`, `creator`, `mediatype=audio`, `collection=librivoxaudio` и 481 файл, включая M4B, JPEG и MP3. Для треков фильтровать `files` по формату/расширению и смотреть `source`, `size`, `title`, duration при наличии; не считать каждый файл главой, потому что архив содержит производные и служебные файлы. Обложку выбирать по конкретному файлу из списка, не по предположению о filename.
- [Правила автоматического доступа IA](https://archive.org/developers/bots.html) требуют описательный `User-Agent` с именем/версией клиента; для AI-агентов дополнительно модель. Они просят задержки в массовых операциях, кэш, обработку 429 и `Retry-After`. Обычная публичная Metadata Read не требует авторизации, кроме некоторых user JSON полей; запись требует авторизации ([официальный MDAPI](https://archive.org/developers/metadata.html)). Доступность конкретного аудио и его права определять на уровне item, не по одному `mediatype=audio`.
- **Фикстуры:** search JSON на 2 item; сокращённый metadata JSON для `letters_brides_0709_librivox` с 2 MP3, одним M4B, JPEG и служебным файлом; пустой `{}` для неизвестного identifier; item с недоступным/без аудиофайлов для graceful degradation. Отдельно проверить HEAD/Range для выбранного файла, а также фактическую лицензию item перед использованием как демонстрационного контента.

## Audiobookshelf

- [Официальная справка API](https://api.audiobookshelf.org/) документирует Bearer user API token; token можно получить через `POST /login`, а GET допускает query `token`. Использовать заголовок `Authorization: Bearer …`, чтобы не помещать секрет в URL/логи. **Справка сама сообщает, что устарела и больше не поддерживается**, поэтому все конечные точки и схемы ниже — гипотезы для contract test на целевой версии сервера, а не гарантии.
- В справке показаны `GET /api/libraries`, `GET /api/libraries/<ID>/items`, `GET /api/libraries/<ID>/search?q=<encoded>&limit=…` ([раздел Search a Library](https://api.audiobookshelf.org/)). Search возвращает `book`/`podcast`, где результат содержит `libraryItem`; пример книги содержит `id`, `libraryId`, `mediaType`, `metadata.title`, `authors`, `narrators`, `series`, `language`. Это локальная библиотека конкретного сервера, не общий публичный поисковик.
- `GET /api/items/<ID>?expanded=1&include=progress` описан для деталей и `userMediaProgress` ([раздел Get a Library Item](https://api.audiobookshelf.org/)); книга имеет `audioTracks`, `chapters`, duration и `contentUrl` у трека в примере. `GET /api/items/<ID>/cover?width=…&height=…&format=…` возвращает изображение, с `raw=1` — исходник ([раздел Cover](https://api.audiobookshelf.org/)). `POST /api/items/<ID>/play` создаёт playback session с треками; `PATCH /api/me/progress/<ID>` описан для прогресса ([раздел Playback](https://api.audiobookshelf.org/)). Path `contentUrl` интерпретировать относительно base URL сервера и проверить требование auth для медиа на своей версии.
- **Фикстуры:** обезличенные ответы `libraries`, `search` (книга/пусто), `item?expanded=1&include=progress` (2 трека и главы), `play` session, `cover` 200/404, auth 401/403, пропавший item. Удалять токены, домашние IP, абсолютные filesystem paths, имена пользователей. Проверить серверный version в `/status` или login response и закрепить версию фикстур. Без живого сервера не заявлять capability `download`/Range или правила refresh токена как подтверждённые.

## Local Folder через SAF

- [Android SAF guide](https://developer.android.com/training/data-storage/shared/documents-files) описывает `ACTION_OPEN_DOCUMENT_TREE` (API 21+): пользователь выбирает дерево, приложение получает доступ к файлам и подкаталогам. Можно сохранить grant через `ContentResolver.takePersistableUriPermission`; перемещение/удаление документа может аннулировать доступ, несмотря на persist. Никакой сетевой auth и сервер здесь не нужны; системный picker является явным согласием пользователя.
- Начиная с Android 11, выбор корня внутреннего/надёжного SD-тома и `Download` через tree picker ограничен; `Android/data` и `Android/obb` также исключены ([Android 11 storage](https://developer.android.com/about/versions/11/privacy/storage)). UX должен просить пользователя выбрать доступную подпапку, не обещая выбор произвольного корня.
- [DocumentsContract.Document](https://developer.android.com/reference/android/provider/DocumentsContract.Document) определяет opaque, provider-specific durable `COLUMN_DOCUMENT_ID`, display name, MIME, size, last-modified и flags. Для идентификатора источника сочетать tree URI + document ID; не использовать файловый путь как универсальный ключ. [DocumentFile](https://developer.android.com/reference/androidx/documentfile/provider/DocumentFile) даёт `listFiles()`, type, name, size, mtime; неизвестные размер/mtime возможны. [MediaMetadataRetriever](https://developer.android.com/reference/android/media/MediaMetadataRetriever) принимает `content://` Uri и может читать duration/embedded art/теги, если формат и provider это позволяют.
- **Фикстуры/device cases:** папка с одним M4B; папка с нумерованными MP3 и cover.jpg; вложенные author/title; одинаковые filename в разных деревьях; нет обложки/тегов; неизвестные size/mtime; revoked grant, удалённый/переименованный файл; cloud DocumentsProvider без локального содержимого. Проверить воспроизведение `content://` после перезапуска приложения/телефона, а также seek и ошибки доступа. Android docs предупреждают, что обход больших деревьев может быть медленным, поэтому индексировать постепенно и кэшировать результаты ([SAF guide](https://developer.android.com/training/data-storage/shared/documents-files)).

## Открытые проверки перед адаптерами

1. LibriVox: устойчивость `listen_url`, Range и поведение 4xx/429; подтверждение введённого предела 500 после даты объявления.
2. IA: единая политика отбора аудиофайлов и прав item; HEAD/Range/редиректы на малом MP3; rate limits на реальной нагрузке.
3. Audiobookshelf: contract test на конкретной версии сервера с согласия пользователя и без вывода токена в лог; справка устарела.
4. Local Folder: SAF-поведение на подключённом Xiaomi и на облачном provider, включая повторное открытие после reboot/revoke.
