# AB-08: Шкала книги, очередь и перерезолв треков

Status: done_with_deviations
Type: implementation
Blocked by: AB-07

## Цель

Создать чистую шкалу треков/глав, PlaybackQueueBuilder и стабильные `vetro-audio` URI, которые при открытии превращаются в свежие URL/headers через `ResolvingDataSource`. Протухание или HTTP 403/410 должно инвалидировать URL и повторить тот же трек с той же позиции один раз. Полный fallback между источниками остаётся AB-25/26.

## Приёмка

- Шкала корректно считает границы треков/глав, прогресс и оставшееся время при скорости. Неизвестная длительность обозначается явно, оценка по размеру/битрейту не выдаётся за точное время.
- URI не содержит секретов и декодирует `VariantId` с двоеточиями/слешами без потерь.
- Очередь содержит metadata книги/глав и работает без нарезки M4B.
- `ResolvingDataSource` никогда не сохраняет подписанные URL в mediaId; после expiry/403/410 получает новый URL, без бесконечного retry.
- JVM-тесты шкалы и Android smoke на единственном тестовом package; debug compile/release build.

## Границы

Настоящий Local Folder источник — AB-09, persistent progress — AB-13, ranking/fallback между источниками — AB-25/26.

## Результат 2026-09-24

- `BookTimeline` считает переходы между файлами, главы, прогресс и оставшееся время с учётом скорости. Неизвестная длительность даёт `null`; оценка по размеру/битрейту помечается `hasEstimates`.
- Очередь использует UUID narration в `mediaId`, URL-адреса и заголовки остаются только в памяти resolver/DataSource. `vetro-audio` URI кодирует `VariantId` через URL-safe Base64; главы внутри M4B не дробят файл.
- `ManifestResolver` обновляет манифест перед истечением срока и после инвалидирования. Сервис при 401/403/410 инвалидирует URL и один раз готовит тот же трек с сохранённой позицией.
- JVM: `BookTimelineTest`, `ManifestResolverTest` — pass. Xiaomi `3871a9d6`: 3 Android smoke-теста — pass (обновление URL/headers, очередь, фоновый сервис и resumption). `:app:assembleRelease` — pass. На телефоне основной Vetro и одна тестовая копия; runner удалён.

## Отклонения и продолжение

- Непосредственный ответ HTTP 403/410 от живого источника ещё не воспроизведён; в AB-17 повторить сценарий со вторым URL и проверкой сохранения позиции. Текущий тест проверяет оба механизма по отдельности: обновление resolver и работа сервиса.
- Динамическое название главы внутри одного M4B в системной шторке проверить и завершить в AB-10 вместе с главами плеера. В AB-08 очередь задаёт главу для начала каждого файла.
- Потоковый `SimpleCache` из черновика spec/04 перенесён к первому онлайн-источнику AB-17: до него есть только Local Folder; отдельный offline download-кэш остаётся AB-34. Ключ кэша должен опираться на логический `vetro-audio` URI.
