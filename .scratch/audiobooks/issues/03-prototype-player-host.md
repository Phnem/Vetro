# AB-03: Прототип — хост плеера «мини ⇄ полный» и стекло над обложкой

Status: DONE_WITH_DEVIATIONS — physical frame budget and Details flight move to AB-10
Type: prototype
Blocked by: AB-02 (для реального `MediaController`; геометрию можно начать на фейковых данных)

## Вопрос, на который отвечает прототип

Можно ли сделать мини-плеер и полный плеер **одним объектом** в корне UI с живым матовым
стеклом над размытой обложкой — без краша `layerBackdrop` и с 60 fps? И можно ли безопасно
лететь обложкой из Details в плеер?

## Объём

- `AudiobookPlayerHost` в `AppNavGraph` над `NavHost` (фейковый стейт, одна обложка).
- `expand: Animatable` 0→1, драг, predictive back, `originRect` через `StagedSheetMotion`.
- Фон плеера (размытая обложка + тинт + зерно) в `layerBackdrop`; 3 кнопки `frostedGlass`
  черновым материалом `playerControl`.
- «Вдавливание» приложения под раскрытым плеером + флаги в `overlayActive`/`effectsSettled`.
- Эксперимент: `sharedElement` на обложке Details → хост; проверить отсутствие SIGSEGV
  (RenderThread) на 20 циклах открытия/закрытия.

## Критерии приёмки

- Видео/гиф прототипа, замер gfxinfo (0 кадров > 32 мс на морфе).
- Вывод в `## Answer`: подход D-04 подтверждён/скорректирован; перелёт обложки из Details —
  да/нет и каким механизмом.
- Код прототипа — в отдельной ветке, в main не мёржится без AB-10.

## Answer

Вывод: D-04 подтверждён как схема одного `AudiobookPlayerHost` над `NavHost`.
Одна поверхность переходит от прямоугольника обложки к мини-плееру и затем к полному экрану;
открытие/сворачивание не пересоздаёт экран. Перелёт реализован через `originRect` + интерполяцию
границ `Animatable`, без `sharedElement` поверх `layerBackdrop`. Источник пока обложка на
`BooksScreen` с fake book; маршрут реальной Details появится позже, так что его интеграция ещё
не подтверждена.

20 циклов на эмуляторе API 37 и на Xiaomi 2211133C (API 36) прошли без падения
RenderThread/SIGSEGV. Проверен обычный back: полный → мини → закрытие. Запись:
[видео 20 циклов](../reviews/assets/ab03-prototype-20-cycles.mp4),
[короткий GIF](../reviews/assets/ab03-prototype-emulator.gif),
[видео с Xiaomi](../reviews/assets/ab03-phone-prototype.mp4),
[GIF с Xiaomi](../reviews/assets/ab03-phone-prototype.gif).

Критерий **0 кадров >32 мс не выполнен**. На Xiaomi без записи экрана сборщик `FrameMetrics`
за 20 циклов показал 18 из 2966 кадров >32 мс (из них: прибытие 2, раскрытие 10,
сворачивание 6), при этом промежуточный `gfxinfo` дал median 9 мс, p95 21–22 мс. Пробное
уменьшение перекрытия двух наборов стеклянных контролов ухудшило результат до 28 из 2966,
поэтому его откатили. Во время записи видео результат — 26 из 2968; видео не используется
для оценки кадров. Полный [`gfxinfo`-снимок](../reviews/assets/ab03-phone-gfxinfo-during.txt)
сохранён. Невыполненный абсолютный порог и интеграция перелёта из настоящего Details —
обязательные проверки AB-10 до переноса кода в main.

На эмуляторе API 37 результат существенно хуже: с записью 505/666 janky frames
(median 46 мс), без записи 273/374 (median 48 мс). Для решения о геометрии опираемся на
физическое устройство, но не подменяем этим проваленный абсолютный критерий.

Пробная оптимизация убрала размытие уже плавного фейкового градиента: тест прошёл за 57,35 с,
`gfxinfo` в середине показал 471/702 janky frames (67,09%, median 38 мс). Перенос чтения
анимации из композиции в измерение/графические слои снова сохранил 20 циклов и back, но дал
лишь 521/789 (66,03%, median 42 мс; тест 55,37 с). Замеры эмулятора вариативны и не
доказывают достижение бюджета. Для настоящей обложки в финальном плеере потребуется
кэшированный размытый фон, а не размытие всего анимируемого градиента на каждом кадре.
