# Подключение внешних сервисов аккаунтом пользователя — ресёрч 2026-09-26

Задача: можно ли дать пользователю подключить свой аккаунт, ключ или сервер (Netflix, ЛитРес, Plex…)
и брать оттуда то, что сейчас без аккаунта недоступно. Пока только проверка, без кода.

## Как проверялось

Аккаунтов у меня нет, поэтому проверялось всё, что можно без входа. Регион машины — Израиль (IL).
1. Главная страница: открывается ли, нет ли гео-блока или Cloudflare. Плюс поиск признаков DRM
   (Widevine / PlayReady / FairPlay / EME) в собственных скриптах сайта.
2. Официальные API: есть ли публичный, что отвечает без входа (данные или корректный 401),
   какой вход (OAuth, код устройства, ключ, пароль).
3. Свои серверы — на публичных демо-экземплярах: вход → каталог → ссылка на поток → Range-запрос.

Признаки DRM на главной — слабое свидетельство: плееры часто грузятся позже. Поэтому вывод о DRM
опирается ещё и на то, как сервис официально отдаёт контент (только своими приложениями, с
Widevine/PlayReady/FairPlay). Ничего не взламывалось и не обходилось.

## Главный вывод

Сервисы делятся на три группы.

1. **Свои серверы и открытые протоколы** — Plex, Jellyfin, Emby, Audiobookshelf, Komga, Kavita,
   Calibre-Web/OPDS, Nextcloud, WebDAV, S3. Подключаются полностью: вход пользователя → каталог → поток
   в плеере Vetro. Проверено вживую. Это главный путь «подключить своё».
2. **Магазины и подписки с защитой (DRM)** — Netflix, Prime, Disney+, Max, Hulu, Apple TV+,
   Paramount+, Peacock, MUBI, Кинопоиск, IVI, Okko, Wink, KION, START, PREMIER, Amediateka, Crunchyroll,
   HIDIVE, ADN, Audible, Kindle, Kobo, Storytel, Bookmate, Everand, Apple Books, VIZ, BookWalker,
   ComiXology и официальные читалки манги. Воспроизводить их в своём плеере нельзя: контент
   зашифрован, ключи выдаются только их сертифицированным приложениям, публичного API для этого нет.
   Обход DRM незаконен (DMCA §1201, ст. 1299 ГК РФ), делать его не будем. Реально сделать:
   - найти, где есть тайтл, и открыть **официальное приложение** на нужном фильме или серии (глубокая ссылка);
   - показать **свою библиотеку/прогресс**, где это даёт официальный API (Spotify, Google Books, Trakt-подобные);
   - синхронизировать отметки «посмотрено/прочитано» у себя.
3. **Серое** — ЛитРес: купленные аудиокниги сервис сам разрешает скачать в MP3 (без DRM), но доступ к
   библиотеке — только через закрытый API их приложений по логину и паролю. Технически возможно, по
   правилам сервиса — нет. Нужна либо договорённость с ЛитРес (партнёрская программа), либо ручной
   импорт: пользователь скачал MP3 сам → «Мои файлы» / Audiobookshelf.

## 1. Свои серверы и протоколы — подключаются ✅

| Сервис | Вход | Что проверено | В приложении сейчас |
|---|---|---|---|
| **Jellyfin** | логин/пароль → токен (`/Users/AuthenticateByName`) или Quick Connect | демо 12.1.0: вход, каталог (фильмы 11, сериалы 1, музыка 4), `PlaybackInfo` (прямой поток mp4), Range 206 | есть для аниме/кино (`PersonalMediaServerPlaybackSource`); нужно расширить на книги/аудиокниги и библиотеку целиком |
| **Emby** | тот же API, что Jellyfin | публичного демо нет, API-справка доступна | есть вместе с Jellyfin |
| **Plex** | официальная привязка устройства: PIN → пользователь вводит код на plex.tv/link → токен | PIN создаётся (201, есть QR), без токена `resources` → 401 | нет |
| **Audiobookshelf** | логин → Bearer-токен (или API-ключ) | справка API доступна; публичного демо нет | заготовка в плане (AB-источник), `research/sources/audiobookshelf.md` |
| **Kavita** | логин → JWT; у пользователя есть API-ключ для OPDS | демо: вход, библиотеки Books/Comics/Manga, OPDS по ключу — 200 | нет |
| **Komga** | Basic / API-ключ, REST + OPDS | справка OpenAPI доступна; демо нет | нет |
| **Calibre-Web** | Basic, каталог OPDS `/opds` | стандарт OPDS проверен на Project Gutenberg (200); Standard Ebooks теперь требует входа (401) | нет |
| **OPDS (любой)** | нет / Basic / ключ в адресе | Gutenberg, Kavita — 200 | нет |
| **Nextcloud** | Login Flow v2 (браузер → пароль приложения) | живой сервер (disroot, v33): Login Flow v2 выдаёт ссылку и токен опроса; WebDAV без входа → 401, как и должно | WebDAV есть (`WebDavPlaybackSource`), Login Flow нет |
| **WebDAV** | Basic | — | есть для аниме/кино |
| **S3 и совместимые** (AWS, MinIO, Backblaze B2, Cloudflare R2, Yandex Object Storage) | ключ доступа + секрет (подпись SigV4) | анонимный `ListObjectsV2` на публичном бакете — 200; с ключами — стандартная подпись, поток через presigned-ссылки с Range | нет |

Что из этого получается для приложения: один экран «Мои серверы» (адрес + вход/ключ, хранение в
`PlaybackSourceCredentialsStore`, уже зашифрованном), а сервер становится источником сразу для
нужных разделов: Jellyfin/Plex/Emby → кино, сериалы, аниме, аудиокниги; Audiobookshelf → аудиокниги;
Komga/Kavita/OPDS → манга и книги; Nextcloud/WebDAV/S3 → папки с файлами для любого раздела.

**Где смотреть — работает прямо сейчас:** открытый GraphQL JustWatch по «Интерстеллару» в регионе RU
вернул предложения Okko и других с прямыми ссылками на страницу фильма. Официальный вариант того же —
TMDB `watch/providers` (данные JustWatch, нужен бесплатный ключ; без ключа 401). У приложения уже есть
«Где смотреть» (web links engine) — сюда естественно добавить подписочные сервисы пользователя:
отметил «у меня есть Okko и Netflix» → в карточке кнопка «Смотреть в Okko», открывающая приложение.

## Предлагаемый порядок работ

1. **Экран «Мои серверы и хранилища»** — общий для всех разделов: Jellyfin/Emby (расширить
   существующее), Plex (вход по коду), Audiobookshelf, Komga, Kavita, OPDS/Calibre-Web, Nextcloud
   (Login Flow v2), WebDAV, S3. Самая большая отдача: пользователь получает всё своё в плеере Vetro.
2. **«Мои подписки» + «Смотреть в …»** — выбор сервисов пользователя, поиск тайтла через TMDB
   (официальный ключ) или JustWatch и глубокая ссылка в официальное приложение; для RU-сервисов
   так же.
3. **Официальные библиотеки** — Spotify (свои аудиокниги, запуск в Spotify), Google Books (полки,
   прогресс).
4. **ЛитРес** — только после договорённости с сервисом; до неё — ручной импорт купленных MP3.

- DRM-признаки и доступность: `drm_results.jsonl` (в папке проверок сессии).

  resources 401, S3 публичный бакет 200, OPDS Gutenberg 200, OPDS Standard Ebooks 401.

  OPDS 200), Nextcloud disroot (status, Login Flow v2 200, WebDAV без входа 401).
